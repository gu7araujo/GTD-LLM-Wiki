# Horizontal vs. vertical: inbox processing and back-of-envelope planning

> [!question] Prompt
> As perguntas do planejamento "verso de envelope" são basicamente as mesmas de quando se processa um
> item da caixa de entrada? O [[inbox-processing-template|template de processamento]] também serviria
> para o planejamento verso de envelope?

## Answer

Partly. The **core four** fields are identical — propósito / princípios / resultado / próxima ação —
because they *are* phases 1, 2 and 5 of the [[natural-planning-model]], and
[[natural-planning-model|"verso de envelope"]] is simply that model run informally (p88-90).

The **rest** of the inbox template is the horizontal [[clarify]] decision tree, and it does not
transfer: by the time you are sketching on an envelope, "exige ação?", "2 minutos?", "delegar?" and
"é projeto?" are already answered.

Allen names the two modes directly (p88): **horizontal focus** is clear outcomes + next actions held
in a trusted system, and covers most situations; **vertical focus** is thinking one project through,
and kicks in only when a project needs more rigor.

> Na maioria das situações, o foco horizontal é tudo que você precisará. Porém, às vezes, pode ser
> necessário mais rigor e foco para manter um projeto ou situação sob controle. É aí que entra o foco
> vertical. p88

So inbox processing is a **funnel** whose narrow end — the minority of items that turn out to be real
projects — opens into back-of-envelope planning.

## Supporting detail

| Field | Inbox processing (horizontal) | Back-of-envelope (vertical) |
| --- | --- | --- |
| Exige ação? (lixo / incubar / referência) | Essential — the first question (p66) | N/A — already an actionable project |
| Regra dos 2 minutos | Essential (p66) | N/A — a 2-min item never earns vertical focus |
| Delegar? / Waiting For | Essential (p66) | Marginal — appears inside organização as a dependency |
| É projeto ou ação única? | Essential — gates the template (p50) | Already answered yes |
| Propósito / princípios | Only for projects | **Core** (p96-99) |
| Resultado / visão | Only for projects | **Core** (p101) |
| Brainstorming | Optional | **Core** — phase 3, the *how* (p103) |
| Organização (componentes / sequência / prioridade) | Optional | **Core** — this *is* the envelope (p109) |
| Próxima ação + contexto | Essential | **Core** (p110) |
| Regra de navegação (p112) | Useful | **Core** |

The book's stop rule applies at both ends — "Até que nível desse modelo de planejamento você precisa
detalhar? Tanto quanto for necessário para tirar um projeto da sua mente" (p111) — and most inbox
items need only "exige ação? → próxima ação".

**Design implication:** two templates, or one with a gate. A short clarify note (exige ação? →
2 min? → delegar? → projeto?) that, when the answer is *projeto*, spawns a project note carrying the
full five phases — including the brainstorming and organização fields the inbox note can omit. The
field-level detail for the inbox half lives in [[inbox-processing-template]].
